# templates/ —— 成片模板

成片的画面是**五层用 ffmpeg 叠出来的**。这里放的是除视频素材外的四层，以及一个用来调版的预览台。

```
┌──────────────────────────────────────────────────────┐
│ ⑤ 文字层    text.html → Edge 无头截图 → PN  │ 每首不同（分数/判定/曲名/评语）
├──────────────────────────────────────────────────────┤
│ ④ 装饰层    bg16-9.png / bg4-3.png（RGBA，带洞口） │ 固定（面板/标签/边框）
├──────────────────────────────────────────────────────┤
│ ③ 曲绘层    data/jackets/256/<song_id>.jpg（160×159）│ 每首不同
├──────────────────────────────────────────────────────┤
│ ② 视频层    谱面录像片段（934×526 或 855×641）      │ 每首不同
├──────────────────────────────────────────────────────┤
│ ① 背景层    曲目背景 + 高斯模糊（1920×1080）        │ 每首不同
└──────────────────────────────────────────────────────┘
```

> ⚠️ **曲绘必须在装饰层下面。** 那个 160×159 的方口是装饰层上**挖的洞** ——
> 曲绘放上面会盖住洞口周围的边框。图层顺序：背景 → 视频 → **曲绘** → 装饰层 → 文字。

> ⚠️ **曲绘口两套模板完全一样**（`x=1289 y=312 160×159`），因为 4:3 那套是复制改的窗口。
> 所以它不放在模板配置里，只留一份。

| 文件 | 说明 |
|---|---|
| `bg16-9.png` | **装饰层（16:9）**。PS 导出，1920×1080 RGBA，背景区域透明 |
| `bg4-3.png` | **装饰层（4:3）**。同上，只是视频窗口是 4:3 |
| `text.html` | **文字层**。透明底，只有随曲目变化的文字 |
| `fonts/` | **打包的字体**。Exo 2 三个字重（451KB）+ `OFL.txt` 许可证 |
| `preview.html` | **预览台**。把五层在浏览器里叠起来，可切换模板，调坐标用 |
| `README.md` | 本文件 |

## 工作流

```
改 text.html  →  刷新 preview.html  →  看效果  →  满意  →  跑管线出片
                     ↑                                    ↓
                     └────────── 不满意，继续调 ←───────────┘
```

**为什么要有预览台**：完整管线（Edge 截图 → ffmpeg 合成）一轮十几秒，排版根本没法迭代。
预览台用 CSS 叠同样的四层，改完刷新即可。

```bash
# 直接双击打开就行，file:// 就够用
start templates/preview.html
```

### 预览台的操作

| 操作 | 快捷键 |
|---|---|
| 参考网格（100px 细线 / 500px 亮线，带坐标标注） | `G` |
| 背景 / 视频 / 装饰 / 文字 图层开关 | `1` `2` `3` `4` |
| 背景切换（10 张候选，跨不同风格） | 下拉框 |
| 模糊强度 | 滑块 |

**顶栏右侧实时显示鼠标处的 1920×1080 坐标** —— 量坐标不用回 PS。

> 视频层需要 `templates/clip.mp4`。没有的话会显示虚线占位框，不影响调文字坐标。

## 关键坐标（实测，不是估的）

从装饰层的 alpha 通道量出来的**完美矩形**（填充率 100%，半透明像素只有 10 个）：

```
                    视频窗口                          曲绘口
16:9 模板   x=20    y=157   w=934  h=526      x=1289  y=312  w=160  h=159
4:3  模板   x=58    y=95    w=855  h=641      x=1289  y=312  w=160  h=159
```

**两套模板的曲绘口完全一样**（4:3 那套是复制改的窗口），只有视频窗口不同。

- 16:9 窗口宽高比 **1.7757**（16:9 差 0.12%）
- 4:3 窗口宽高比 **1.3339**（4:3 差 0.05%）

> 坐标是从装饰层的 **alpha 通道连通域分析**量出来的，不是眼睛估的。
> 换模板/改版式后要重新量（方法见 `scripts/README.md`）。

judgement 面板里，`PURE` / `FAR` / `LOST` **标签是烤在装饰层里的**，数值要放在标签**右侧**：

```
PURE 标签右边界  x≈1469
FAR  标签右边界  x≈1451
LOST 标签右边界  x≈1441
→ 数值起点建议 x≈1490
```

## 为什么需要两套模板

实测 catalog 里 **871 个视频来源**的画幅：

| 画幅 | 来源数 | 占比 |
|---|---|---|
| 1920×1080（16:9） | 544 | 62.5% |
| 1920×1440（4:3） | 170 | 19.5% |
| 2732×2048（4:3） | 97 | 11.1% |
| 3840×2880（4:3） | 58 | 6.7% |
| 2880×2160（4:3） | 2 | 0.2% |

按谱面算：**321 / 645（49.8%）根本没有 16:9 的来源**。

把 4:3 塞进 16:9 的窗口，`cover` 会裁掉 **25% 的高度** —— 谱面录像的游玩区会被切。
所以画幅信息在**构建期**就存进了 catalog（`sources[].video_width/height`，零额外请求，
`view` 接口本来就返回），渲染层据此选模板，**不需要先下载**。

> 4:3 模板的窗口更大（855×641 vs 934×526），因为 4:3 更高，能塞下更多画面。

## ⚠️ 已知的坑

### 1. CSS 模糊 ≠ ffmpeg 模糊

同一张图分别处理后跟未模糊原图比相似度：

| 处理 | PSNR（越低=越糊） |
|---|---|
| CSS `blur(25px)` | 20.12 |
| ffmpeg `gblur=sigma=25` | 21.97 |
| ffmpeg `gblur=sigma=10` | 24.80 |

**CSS `blur(N)` ≈ ffmpeg `gblur=sigma(N × 1.3)`。** 预览台里已经按这个系数校准过：
滑块上的数字是 **ffmpeg 的 sigma**，内部会除以 1.3。

> 另外 CSS 模糊会把边缘"吃掉"露出底色，而 ffmpeg 的 `gblur` 是 clamp 边界不会 ——
> 所以预览台给背景加了一点点 `scale` 补偿，否则会看到一圈暗边。

### 2. 导出 PNG 时 `html` / `body` 不能有背景色

少这一句，Edge 截出来就是不透明底，整层会盖死下面的内容。

### 3. 数字必须 `tabular-nums`

否则 `10,001,127` 和 `9,999,999` 宽度不同，**切歌时整个版面会左右跳**。

### 4. 字体：已经打包进 `fonts/`，不要再用系统字体名

**原来的写法有问题**：`text.html` 里写的是 `"Exo 2 Medium"` / `"Exo 2 Light"` /
`"Noto Sans SC Medium"` —— 这些是**本机已安装**的字体名。换一台机器（尤其是最终用户的机器）
就全部回退，版式全变。

现在 Exo 2 三个字重已经打包进来（共 451KB，**SIL OFL 1.1，可自由分发**）：

```
fonts/Exo2-Light.ttf    300
fonts/Exo2-Regular.ttf  400
fonts/Exo2-Medium.ttf   500
fonts/OFL.txt           ← 打包 OFL 字体必须附许可证
```

用 `@font-face` 声明成一个族名 `"Exo 2"`，靠 `font-weight` 选字重。

> **验证方法**（想确认打包真的生效时用）：`@font-face` 起一个系统里不存在的族名
> （比如 `ZZTESTFAMILY`）指向打包的字体，再用一个不存在的族名做对照。
> 前者渲染成 Exo 2、后者明显不同 → 说明浏览器真的加载了文件而不是回退到系统字体。

⚠️ **CJK 必须走兜底链。** Exo 2 只有拉丁字形，而 Arcaea 的曲名/曲师大量是日文和中文
（「削除」「さよならはつこい」）。原来 `.song { font-family: "Exo 2 Medium" }` **没有兜底**，
中日文会掉到浏览器默认字体 —— 换机器 / 换 locale 就变样。现在所有声明都写成：

```css
font-family: "Exo 2", "Microsoft YaHei", "Noto Sans SC", sans-serif;
```

> 做应用时这里要换成**子集化打包的 CJK 字体**（Noto Sans SC 全量 16.9MB 太大，
> 按项目预算应当子集到 3–8MB）。子集化后放进 `fonts/`，插到兜底链首位即可。

**绝对不要用游戏原版字体**（铁律 8，竞品仓库里就有这个侵权项）。

### 5. 图层命名对应关系

| 本文件里的叫法 | 说明 | 当前文件 |
|---|---|---|
| 装饰层 | 面板/标签/边框，固定不变 | `bg16-9.png` / `bg4-3.png` |
| 文字层 | 会随曲目变化的文字 | `text.html` → 截图 |
| 背景层 | 曲目背景 + 高斯模糊，每首不同 | `data/backgrounds/960/Background_<bg>.jpg` |
| 视频层 | 谱面录像片段 | 由管线生成 |

### 6. 难度底板（不是文字变色）

难度是靠**文字底部的色块**区分的，文字始终白色。
**不需要为每种难度导出 PNG** —— 文字层是 HTML，底色就是一行 `background-color`。

#### 形状：不是矩形，是设计里那块斜切色块

SCORE 面板下方那条横条**右端有一块颜色不一样的色块**，那就是难度的位置。
它的形状是从装饰层像素里量出来的**斜边梯形**：

```
顶点（顺时针）  左上 (1713, 269) → 右上 (1920, 269)
                右下 (1920, 326) → 左下 (1649, 326)
外框            left=1649  top=269  271×57
斜边水平投影    64px（1713 − 1649），斜率 dx/dy ≈ −1.14（约 45°）
```

CSS 用 `clip-path: polygon(64px 0, 100% 0, 100% 100%, 0 100%)` 还原。
**改形状只动 `--diff-x/y/w/h/slant` 五个变量**，clip-path 会跟着走。

> 验证方法（想确认盖得准不准时用）：把底板设成一个和品红反差最大的颜色（如 Past 的蓝），
> 叠到装饰层上，再扫描原来那块品红的范围还有没有残留像素。
> 实测残留 0（只有边界抗锯齿的几十个像素）。

#### 配色

取自 wiki 的 `MediaWiki:Common.css`。它有**浅色/深色两套**，正好分工：

| | 特点 | 用途 |
|---|---|---|
| **浅色主题** | 深且饱和 | → **底板色**（白字压上去对比度够） |
| 深色主题 | 浅色粉彩 | → 只适合当文字色，这里不用 |

| 难度 | 底板色 | class |
|---|---|---|
| Past | `#0a82be` | `d-pst` |
| Present | `#648c3c` | `d-prs` |
| Future | `#50194b` | `d-ftr` |
| Beyond | `#822328` | `d-byd` |
| Eternal | `#5d4e76` | `d-etr` |

注入方式：`text.html?...&diffClass=ftr` → `.diff` 上挂 `d-ftr`。

> 没拿到难度信息时有一个中性兜底底色（`rgba(255,255,255,.14)`），不会裸奔。

### 7. 自动字号（`data-fit`）

右侧文字列只有约 **390px** 宽，而最长曲名
`Hiiro Gekka, Kyoushou no Zetsu (nayuta 2017 ver.)` 在 54px 下要 **1400px**，
533 首里有 **150 首**放不下。纯缩字号会缩到 16px 没法看，所以分两阶段：

```
阶段一  单行内逐像素缩小，缩到 --fit-min（曲名 34px）为止
阶段二  还放不下就允许换行（最多 --fit-lines 行），继续缩到 --fit-hard（26px）
```

**两个必须注意的点**：

1. **必须在 `document.fonts.ready` 之后量** —— 否则量到的是回退字体的宽度，字体会跳。
2. **曲名和曲师必须流式排布**（同一个容器里自然堆叠），不能各自钉死 y 坐标 ——
   曲名换行成 2 行时，固定坐标会让第二行压到曲师头上（踩过）。

## 渲染文字层

```bash
msedge --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=1920,1080 --default-background-color=00000000 \
  --virtual-time-budget=3000 --screenshot=text.png file:///.../templates/text.html
```

- `--default-background-color=00000000` **不能省** —— 它是"默认背景透明"的开关
- `--force-device-scale-factor=1` 防止高分屏上截出 2 倍图
- Edge 会打印一条 `QQBrowser user data path found` 之类的报错 —— **无害噪音**
- 输出应当是 1920×1080 且 `pix_fmt=rgba`，用 `ffprobe` 确认

## 合成四层

```bash
ffmpeg -y \
  -i clip.mp4 \
  -loop 1 -framerate 30 -i bg_blur.png \
  -loop 1 -framerate 30 -i "bg16-9.png" \
  -loop 1 -framerate 30 -i text.png \
  -filter_complex "\
[0:v]fps=30,scale=934:526:force_original_aspect_ratio=increase,crop=934:526,setsar=1[vid];\
[1:v]format=rgba[bg];[2:v]format=rgba[ch];[3:v]format=rgba[tx];\
[bg][vid]overlay=20:157:format=auto[o1];\
[o1][ch]overlay=0:0:format=auto[o2];\
[o2][tx]overlay=0:0:format=auto[v]" \
  -map "[v]" -t 10 \
  -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -g 60 -keyint_min 60 -sc_threshold 0 \
  seg_001.mp4
```

**参数必须锁死**（§7.4）：分辨率 / SAR / 帧率 / 像素格式 / 编码器 / GOP。
任一项不一致，最后 `-c copy` 拼接就会出问题。

背景层用：

```bash
ffmpeg -y -i "data/backgrounds/960/Background_<bg>.jpg" \
  -vf "scale=1920:1080:force_original_aspect_ratio=increase,crop=1920:1080,gblur=sigma=25" \
  bg_blur.png
```

## 这个预览台还是 P4 的原型

架构决策 2 说「**模板 = HTML/CSS，WebView2 就是渲染器**」——
`preview.html` 就是那句话的最小实现：同一个 `text.html`，
在浏览器里是预览、在 ffmpeg 里是图层、将来在 Wails 的 WebView2 里就是实时预览。

所以在这里踩过的坑（透明底、字体、等宽数字）将来都会原样复用。
